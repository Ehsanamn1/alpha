# یادداشت فنی: Spoof Tunnel

مخزن مورد بررسی: https://github.com/ParsaKSH/spoof-tunnel

## وضعیت قابل مشاهده در مخزن

- زبان هسته: Go به همراه اجزای Rust برای پردازش بسته‌ها.
- مجوز اصلی مخزن: Apache-2.0.
- مخزن یک کلاینت و سرور تونل دارد و ارسال/دریافت بسته‌های با آدرس مبدأ دستکاری‌شده را پیاده می‌کند.
- README نسخه‌های جدیدتر می‌گوید هسته از نسخه ۲ به یک UDP pipe ساده تبدیل شده و رمزنگاری و سازوکار اطمینان‌پذیری نسخه قدیمی از هسته حذف شده است.
- README استفاده از یک مسیر WireGuard محلی را برای تونل امن‌تر پیشنهاد می‌کند.
- کد به مجوزهای سطح پایین سیستم و دو گره سازگار نیاز دارد؛ در نتیجه آداپتور عمومی SOCKS5 به‌تنهایی برای ادغام کافی نیست.

## پرسش‌های لازم برای پذیرش

1. آیا مسیر رفت و برگشت از هر دو سمت، در شبکه‌ای که خودمان کنترل می‌کنیم، برقرار می‌شود؟
2. آیا میزبان‌ها و شبکه‌ها ارسال بسته‌های موردنیاز را مجاز می‌دانند؟
3. آیا ترافیک کاربر قبل از ورود به UDP pipe با یک تونل دارای رمزنگاری و احراز هویت مستقل محافظت می‌شود؟
4. رفتار در افت بسته، MTU، NAT، تغییر IP و ری‌استارت چیست؟
5. آیا ابزار بدون اجرای root غیرضروری یا دسترسی بیش از حد قابل راه‌اندازی است؟
6. آیا نسخه دقیق و checksum باینری‌ها بررسی و منشأ انتشار قابل اعتماد است؟

## تصمیم فعلی

فعلاً فقط به‌عنوان آداپتور تحقیقاتی در نقشه راه است. تا زمانی که مسیر امن، کارکرد دوطرفه و سازگاری آن با یک رابط شبکه محلی در تست‌ها اثبات نشود، نباید به‌عنوان مسیر پیش‌فرض یا راه‌حل تضمینی خاموشی معرفی شود.

این یادداشت ممیزی کد کامل یا اثبات امنیت Spoof Tunnel نیست؛ بررسی عمیق کد باید جداگانه انجام شود.
