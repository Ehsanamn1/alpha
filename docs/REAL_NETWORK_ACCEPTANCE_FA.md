# راهنمای پذیرش روی شبکه و نود واقعی Alpha

این راهنما برای آزمون روی دستگاه خودت است. CI نمی‌تواند کیفیت اینترنت ISP، محدودیت‌های اپراتور یا اعتبار یک نود عمومی را ثابت کند.

## پیش‌نیازها

- Alpha و موتور رسمی sing-box نصب باشند.
- یک اشتراک یا کانفیگ واقعی را در پنل Alpha وارد کرده باشی.
- پنل محلی باز باشد و از طریق «اتصال هوشمند» اتصال را صریحاً فعال کرده باشی.
- پنل و پراکسی فقط روی loopback محلی بمانند؛ پورت مدیریتی را روی شبکهٔ عمومی باز نکن.

## Windows

در پوشهٔ استخراج‌شده پنل را اجرا کن:

```powershell
.\alpha-windows-amd64.exe ui --config .\config.json --no-open
```

در پنل `http://127.0.0.1:18888` برو، نود واقعی را وارد کن و «اتصال هوشمند» را فعال کن. در ترمینال دوم اجرا کن:

```powershell
.\alpha-windows-amd64.exe smoke --config .\config.json --timeout 30s
```

## Linux

```bash
./alpha-linux-amd64 ui --config ./config.json --no-open
# در پنل نود واقعی را صریحاً وصل کن؛ در ترمینال دوم:
./alpha-linux-amd64 smoke --config ./config.json --timeout 30s
```

## تفسیر نتیجه

- `[OK]` یعنی حداقل یک درخواست HTTP/HTTPS از پراکسی SOCKS5 خود Alpha و نود متصل‌شده عبور کرده است. این نتیجه نقطه‌ای است؛ دسترسی دائمی یا دسترسی به همهٔ دامنه‌ها را ثابت نمی‌کند.
- `[FAIL]` یعنی هیچ مقصد آزمونی در بازهٔ زمانی تعیین‌شده موفق نشده است. بخش Routes/Diagnostics پنل را بررسی کن؛ خروجی عمومی عمداً URLها و رمزهای کانفیگ را چاپ نمی‌کند.
- برای آزمون fallback دریافت منابع، ابتدا یک مسیر واقعی را وصل کن؛ سپس در Sources یک منبع HTTPS یا کانال عمومی تلگرام اضافه کن و «همگام‌سازی الآن» را بزن. بررسی کن که منبع به‌روزرسانی شده و کانفیگ قابل‌واردسازی دریافت شده باشد. این کار فقط وقتی ممکن است که منبع از مسیر جایگزین قابل دسترسی باشد.
- تست کنترل‌شدهٔ CI با یک سرور TLS محلی، جایگزین آزمون ISP واقعی نیست.

**حریم خصوصی:** برای گزارش مشکل فقط خروجی `[OK]`/`[FAIL]` و وضعیت کلی را به اشتراک بگذار. `config.json`، `catalog.json`، URI کامل کانفیگ، لینک اشتراک محرمانه یا توکن نشست پنل را منتشر نکن.
