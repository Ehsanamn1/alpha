# معماری Alpha

## چرخهٔ خودکار کانفیگ در 0.4.4-alpha

1. هنگام اجرای پنل محلی، چهار کانال عمومی تلگرام یک‌بار به catalog اضافه می‌شوند.
2. Alpha پیش‌نمایش عمومی کانال‌ها را می‌خواند، لینک‌های قابل‌پشتیبانی را استخراج و parse می‌کند و هر ۱۵ دقیقه منابع را دوباره بررسی می‌کند.
3. پس از پیدا شدن کانفیگ، کاربر تنها با یک کلیک روی «اتصال هوشمند» موتور sing-box را اجرا می‌کند؛ فایل کانفیگ قبل از اجرا اعتبارسنجی می‌شود و گروه URL-test نود پاسخ‌گو را انتخاب می‌کند.
4. URL منابع در catalog خصوصی باقی می‌ماند و از API مرورگر پنهان است.

دریافت اولیه به دسترسی Telegram وابسته است. اگر Telegram و منابع عمومی جایگزین مسدود باشند و مسیر فعالی وجود نداشته باشد، برنامه نمی‌تواند خودش از هیچ دسترسی شبکه بسازد. نودهای عمومی ناشناس‌اند و از نظر امنیت یا پایداری تضمین نمی‌شوند.

## اجزای فعلی

1. **موتور خارجی:** پراکسی یا هسته‌ای که روی دستگاه/سرور کاربر اجرا می‌شود و یک SOCKS5 محلی ارائه می‌کند.
2. **Health probe:** از طریق SOCKS5 اتصال CONNECT می‌سازد، TLS را تأیید می‌کند و پاسخ HTTP/HTTPS را می‌خواند.
3. **Orchestrator:** سلامت، اولویت، تأخیر و علت خطا را نگهداری و دوره‌ای به‌روز می‌کند.
4. **SOCKS router:** یک endpoint ثابت روی loopback ارائه می‌دهد و اتصال‌های جدید را از مسیر سالم عبور می‌دهد.
5. **Process supervisor:** اجرای باینری خارجی فقط پس از پیکربندی صریح و دادن flag مجاز است.
6. **Local UI:** داشبورد محلی از وضعیت موتور می‌خواند و فقط اجازه Probe دستی دارد. سرور UI فقط روی loopback bind می‌کند و API آن session token دارد.

## چرا قرارداد SOCKS5؟

این رابط مرزی اجازه می‌دهد چند هسته مستقل را بدون اتصال کد داخلی پروتکل‌های مختلف به یکدیگر آزمایش کنیم. در این نسخه فقط `external-socks5` و `managed-socks5` به مسیر روتر وارد می‌شوند. موتورهایی که به TUN/IP نیاز دارند یا صرفاً فید/پیام‌رسانی انجام می‌دهند، به‌عمد در روتر SOCKS5 ادغام‌شده محسوب نمی‌شوند.

## Failover

- سلامت موتور با درخواست HTTP/HTTPS واقعی بررسی می‌شود.
- مسیرها با اولویت و سپس تأخیر رتبه‌بندی می‌شوند.
- هنگام شکست اتصال به پراکسی یا دست‌دهی، اتصال جدید مسیر بعدی را امتحان می‌کند.
- تونل قطع‌شده، تضمین حفظ یک اتصال موجود را ندارد؛ مهاجرت بی‌وقفه جریان TCP قابلیت جداگانه‌ای است.

## امنیت UI

- loopback-only bind؛ به LAN یا اینترنت expose نمی‌شود.
- توکن تصادفی جلسه برای actionهای POST.
- بررسی Origin و عدم ارائه CORS.
- CSP و هدرهای ضد framing/MIME sniffing.
- APIها از service-worker cache مستثنا هستند.

## مرزهای پروژه

- Diban/MasterHttpRelayVPN/Zyrln/LTSC: روش‌های رله‌ای که همچنان به مسیر رله وابسته‌اند.
- sing-box/Xray/Tor/Psiphon: هسته‌های خارجی که ممکن است یک SOCKS5 محلی فراهم کنند.
- Spoof Tunnel: روش لایه پایین با پیش‌نیازهای شبکه و امنیت مجزا؛ هنوز adapter ندارد.
- iodine: تونل DNS که در این نسخه به TUN/IP یا پراکسی سازگار نیاز دارد.
- TheFeed: ارتباط اضطراری محدود، نه full-tunnel.
- GoodbyeDPI/zapret: ابزارهای مخصوص انواعی از DPI؛ ورودی SOCKS5 ارائه نمی‌کنند.

این مسیرها همیشه با هم جمع‌پذیر نیستند؛ برخی باید جایگزین هم باشند، برخی زنجیره شوند و برخی فقط برای پیام‌رسانی کار کنند. ادغام بر اساس قرارداد، threat model و تست پذیرش جداگانه انجام خواهد شد.
